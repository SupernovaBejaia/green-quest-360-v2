# Green Quest 360 — V2 (version de test)

- **Adresse de test :** <https://supernovabejaia.github.io/green-quest-360-v2/>
- **La V1 ne bouge pas :** <https://supernovabejaia.github.io/green-quest-360/>

Les deux apps sont séparées : stockage, cache hors ligne, déploiement du script Google et dépôt GitHub. On peut installer les deux sur le même téléphone. L'icône de la V2 porte un badge orange « V2 ».

## Ce qui change par rapport à la V1

### 1. Contrôle qualité immédiat, sur le terrain
- **Photo floue = photo refaite.** À chaque déclenchement, l'app mesure la netteté et la compare aux autres photos du même anneau. Une photo bougée est refusée tout de suite (« Photo floue, on la refait ») ; au bout de 2 essais, elle est gardée mais signalée. Le ciel uni n'est pas contrôlé, car il n'y a pas de détail à juger.
- **Anti-bougé.** Après le maintien sur le point, l'app attend que le téléphone soit vraiment immobile avant de déclencher.
- **Téléphone penché.** Si le téléphone est incliné sur le côté, l'app affiche « Gardez le téléphone droit ».
- **Reprise ciblée.** Après l'assemblage, l'app indique les photos mal raccordées (téléphone déplacé, objet trop proche, personne qui passe, flou) et propose de reprendre **seulement celles-là**, sans refaire tout le tour. Le capteur d'orientation reste allumé entre la prise et la reprise, pour que les nouvelles photos se placent exactement au bon endroit.

### 2. Un dossier Drive par participant
```
Green Quest Cartographie/
  Relevés Green Quest 360          ← tableau : colonnes « Photo 360 propre (HD) » et « Version » ajoutées
  Amina Bélaïd/

      meta.json
      sources/source_01.jpg …
```

### 3. Envoi en arrière-plan
- **Android (Chrome)** : dès que le téléphone retrouve du réseau, le navigateur envoie les photos tout seul, **même si l'app est fermée**.
- **iPhone** : Apple ne permet pas l'envoi en arrière-plan pour les web apps. Les photos partent dès qu'on **ouvre l'app** avec du réseau.

### 4. Version propre automatique (robot)
Toutes les 10 minutes, un robot gratuit sur GitHub (dépôt `green-quest-360-v2`, onglet *Actions*) cherche les photos arrivées dans le Drive. Pour chacune, il :
1. repart des photos sources et de l'orientation calculée par le téléphone ;
2. égalise l'exposition par zones ;
3. place les raccords avec des **coutures intelligentes** : ils passent là où les photos se ressemblent, ce qui évite de couper un objet ou une personne et supprime les « fantômes » transparents ;
4. fond les photos en multi-bandes ;
5. dépose `…_360_HD.jpg` (jusqu'à 8192 px) dans le dossier du participant et met le lien dans le tableau.

Les participants n'ont rien à faire.

**Limites honnêtes :**
- Une personne qui a bougé entre deux photos peut apparaître deux fois, nette. Avec seulement deux vues de cette zone, impossible de savoir quelle position garder.
- Un téléphone vraiment déplacé de plusieurs mètres en pleine prise laisse des défauts.
- Seuls le ciel et le sol manquants sont reconstitués, jamais le sujet.

## Mise en service du robot (une seule fois)
Dans un terminal, dans le dossier du projet :
```bash
bash tools/setup-bot-key.sh
```
Le script génère une clé secrète, la donne au script Google V2 (qui refuse ensuite toute autre clé) et l'enregistre dans les secrets GitHub du dépôt V2. La clé n'est écrite nulle part en clair.

Pour lancer le robot tout de suite, sans attendre les 10 minutes :
```bash
gh workflow run hd-bot.yml -R SupernovaBejaia/green-quest-360-v2
```

## Republier la V2 après une modification
Sur la branche `v2`, change d'abord `VERSION` dans `app/sw.js`, puis lance :
```bash
bash tools/publish.sh "message"
```
